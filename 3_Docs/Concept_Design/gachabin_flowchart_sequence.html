GACHA-BIN: แผนผังการทำงานและลำดับขั้นตอนระบบ

All-in-One Smart Vision Recycling & Gamification Kiosk System

ระดับการศึกษา: ประกาศนียบัตรวิชาชีพชั้นสูง (ปวส.)
โครงสร้างซอฟต์แวร์: FastAPI (Backend) + React Kiosk (UI)
ระบบสมองกล: YOLO11n-cls + OpenCV Computer Vision
ระบบควบคุมกายภาพ: HAL Driver (RPi.GPIO / Mock Hardware)

Unified Host Architecture FastAPI + Uvicorn (Port 8000) ทำหน้าที่เป็นทั้ง Static File Server และ API/WS ในตัวเดียว ทำให้เป็น Same-Origin 100% ปลอดปัญหา CORS และประหยัด RAM บน Pi ได้ 150-250MB
Frontend Kiosk Native Lightweight Web (HTML5 + CSS3 + ES6) ฝังเป็น Static Assets ในตัว FastAPI (พอร์ต 8000) รันบน Chromium Kiosk Mode โดยตรง ปลอดภาระ Node.js และประหยัดหน่วยความจำ (RAM) บน Raspberry Pi
Database Storage SQLite 3 + SQLAlchemy (WAL Mode) เปิดใช้ PRAGMA journal_mode=WAL ป้องกันปัญหา Lock Database ขณะสตรีมข้อมูล
ส่วนที่ 2 ผังตรรกะความปลอดภัยการตรวจจับขยะ 4 ขั้นตอน (4-Stage Smart Vision Invariants)
ขั้นตอนควบคุมความถูกต้องของระบบตรวจจับตามหลักวิศวกรรมป้องกันการโกงแต้ม (Anti-Cheat & Noise Immunity)
  • Stage 1 (Presence Gating): ตรวจวัดความต่างของพื้นหลัง ตัด False Positive จากห้องว่าง (0% Error)
  • Stage 2 (Temporal Dwell Hold): วัตถุต้องนิ่งคงที่เป็นเวลา ≥ 1.2 วินาที (≥ 8 เฟรมต่อเนื่อง)
  • Stage 3 (YOLO Inference): โมเดล YOLO11n-cls ตรวจสอบค่าความมั่นใจ (Confidence ≥ 88%)
  • Stage 4 (Item Exit Gate): ล็อกการให้แต้มซ้ำ (waiting_for_exit) จนกว่าขยะจะถูกปล่อยลงถังจริง

ด่านความปลอดภัย เงื่อนไขตัวเลข (Invariant Values) กลไกป้องกันทางเทคนิค (The "Why")
Stage 1: Presence Gate diff_threshold ≥ 8.0 หรือ change ≥ 3.0% ป้องกันไม่ให้โมเดล AI พยายามเดาภาพพื้นหลังห้องว่างเปล่า ซึ่งอาจทำให้เกิด False Positive
Stage 2: Temporal Dwell hold_duration ≥ 1.2s และ consecutive ≥ 8 frames ป้องกันภาพกระตุก หรือมือผู้ใช้ที่ยื่นผ่านช่องทิ้งชั่วคราว โดยต้องวางวัตถุให้นิ่งจริง
Stage 3: YOLO Inference conf_threshold ≥ 0.88 (88%) กรองวัตถุแปลกปลอม เช่น ขยะทั่วไป กล่องโฟม หรือสิ่งที่ไม่ใช่ขวดพลาสติก/กระป๋องโลหะ
Stage 4: Item Exit Gate waiting_for_exit = True จนกว่าจะตรวจพบห้องว่าง ป้องกันการถือขวดชิ้นเดิมค้างไว้เพื่อให้ระบบนับแต้มเบิ้ลหลายรอบ
ส่วนที่ 3 แผนภาพลำดับเวลาการตรวจจับขยะและการคัดแยกด้วย Dual Servos (Recycling & Dual-Servo Sorting Sequence)
แสดงกระบวนการเปิดเซสชันผ่านการสแกน QR Code บนมือถือ (Single-Session Lock) การตรวจจับขวดด้วย AI Vision 4-Stage การตรวจวัดระดับถังขยะด้วย Ultrasonic HC-SR04 และกลไกคัดแยก 2 จังหวะด้วยเซอร์โวมอเตอร์ MG995 จำนวน 2 ตัว

ส่วนที่ 4 แผนภาพลำดับเวลาการหมุนรางวัลกาชาปอง 20 แต้ม (Gacha True-Random & Raincheck Sequence)
แสดงขั้นตอนการสุ่มรางวัล True Random 3 ระดับ (Special 5%, Rare 25%, Common 70%) การออกรหัสตั๋วรับรางวัล (Claim Code) ระบบจองสิทธิ์รับของย้อนหลังเมื่อของหมดชั่วคราว (Raincheck Flow: waiting_restock) และการยืนยันส่งมอบของรางวัลโดย Super Admin

    API->>DB: ตรวจสอบแต้มสะสมของผู้ใช้ (SELECT score)
    DB-->>API: คืนค่าแต้มสะสมปัจจุบัน

    alt กรณีแต้มสะสมไม่เพียงพอ (< 20 แต้ม)
        API-->>Mobile: คืนค่า HTTP 400 Bad Request ("แต้มสะสมไม่เพียงพอ ต้องการ 20 แต้ม")
        Mobile-->>User: แสดงการแจ้งเตือนให้หยอดขวดเพิ่ม
    else กรณีแต้มสะสมเพียงพอ (>= 20 แต้ม)
        API->>DB: หักคะแนนผู้ใช้ 20 แต้ม (score -= 20)
        API->>API: สุ่มทศนิยมแท้จริง True Random Float R ในช่วง [0, 1)
        Note over API: R < 0.05: พิเศษ (Special 5%)
0.05 <= R < 0.30: แรร์ (Rare 25%)
0.30 <= R < 1.00: ทั่วไป (Common 70%)

        API->>DB: ตรวจสอบสต็อกของรางวัลใน Tier นั้น (stock > 0)
        
        alt กรณีมีของรางวัลในสต็อก (In-Stock)
            API->>DB: หักสต็อกรางวัล (-1) และสร้างบันทึก gacha_spins สถานะ 'pending'
            API->>API: สร้างรหัสตั๋วรับรางวัล เช่น RWD-8F3A
            API->>DB: COMMIT Transaction บันทึกข้อมูลสมบูรณ์
            API-->>Mobile: คืนค่าผลสุ่ม { status: 'won', reward: '...', claim_code: 'RWD-8F3A' }
            Mobile-->>User: แสดงตั๋วรับรางวัลและรหัสอ้างอิงบนหน้าจอมือถือ
        else กรณีของรางวัลระดับนั้นหมดสต็อกชั่วคราว (Raincheck Flow)

    deactivate API

    end
